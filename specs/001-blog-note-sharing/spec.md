# Feature Specification: Personal Blog Notes

**Feature Branch**: `001-web-markdown`
**Created**: 2026-04-24
**Status**: Draft
**Input**: User description: "构建一款个人博客 Web 应用，支持按用户主页浏览与管理笔记、搜索其他用户、Markdown 笔记编辑与只读访问，以及一级文件夹归类。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理个人笔记主页 (Priority: P1)

作为已登录用户，我希望进入自己的主页后能看到自己全部已发布笔记，并按一级文件夹管理这些笔记，以便持续整理学习笔记并快速进入阅读或编辑。

**Why this priority**: 这是产品的核心价值，没有个人主页、文件夹和笔记创建能力，就无法形成可持续记录笔记的最小可用版本。

**Independent Test**: 使用一个已有账号登录后，新建一级文件夹、新建笔记并归入该文件夹，然后在个人主页确认该笔记出现在正确文件夹下，且可以从列表进入详情页。

**Test-First Proof**: 先编写验收测试，验证登录用户能看到自己的笔记列表、每篇笔记必须归属一个文件夹、能从主页创建笔记并进入详情；在实现前这些测试应因主页无数据结构、无创建入口或无归档校验而失败。

**Acceptance Scenarios**:

1. **Given** 用户已成功登录且已有多个文件夹和笔记，**When** 用户进入自己的主页，**Then** 系统展示该用户所有已发布笔记，并按所属一级文件夹归类显示。
2. **Given** 用户位于自己的主页，**When** 用户新建一篇笔记并选择某个一级文件夹保存，**Then** 该笔记立即出现在对应文件夹下，且可进入详情页阅读。

---

### User Story 2 - 编写与编辑 Markdown 笔记 (Priority: P2)

作为笔记作者，我希望笔记使用 Markdown 编写，并在编辑模式与解析展示模式之间切换，还能插入图片，以便既高效记录内容，又能以适合阅读的形式查看最终效果。

**Why this priority**: 记录学习笔记不仅需要保存文本，还需要结构化排版、图片说明和预览能力，这直接决定内容的可用性和阅读体验。

**Independent Test**: 在个人主页打开一篇自己的笔记，切换到编辑模式，输入 Markdown 内容与图片，保存后切回展示模式，确认格式、图片与文件夹归属保持正确。

**Test-First Proof**: 先编写验收测试，验证作者可在自己的笔记中切换编辑/展示模式、保存 Markdown 后正确渲染、插入的图片可在展示模式中看到；在实现前这些测试应因缺少编辑权限、渲染结果或图片展示能力而失败。

**Acceptance Scenarios**:

1. **Given** 用户打开自己的一篇笔记详情页，**When** 用户切换到编辑模式并修改 Markdown 内容后保存，**Then** 展示模式中显示更新后的解析结果。
2. **Given** 用户在编辑模式中插入图片并保存，**When** 用户返回展示模式，**Then** 页面显示图片且与正文内容一并可阅读。

---

### User Story 3 - 搜索并阅读其他用户笔记 (Priority: P3)

作为读者，我希望通过搜索框模糊搜索其他用户账号并进入其主页，只读浏览对方已发布的笔记，以便发现和阅读他人的学习记录。

**Why this priority**: 共享阅读能力是产品区别于单机笔记的关键，但它建立在个人笔记管理能力已经可用的基础之上，因此优先级低于作者侧核心流程。

**Independent Test**: 使用一个非作者账号登录后，通过搜索框输入目标用户账号的部分字符，进入目标用户主页并打开其笔记，确认可以阅读内容但无法编辑。

**Test-First Proof**: 先编写验收测试，验证模糊搜索返回匹配账号、可进入目标主页、可阅读其笔记且任何编辑入口或保存尝试都会被阻止；在实现前这些测试应因搜索、主页跳转或权限限制缺失而失败。

**Acceptance Scenarios**:

1. **Given** 读者已登录并在搜索框输入其他用户账号的部分字符，**When** 系统返回匹配结果且读者选择其中一个账号，**Then** 系统进入该用户主页并展示其全部已发布笔记。
2. **Given** 读者进入其他用户的一篇笔记详情页，**When** 读者浏览该页面，**Then** 只能看到只读内容，且不能进入编辑模式或保存修改。

---

### Edge Cases

- 当搜索框没有匹配任何账号时，系统如何明确提示“无匹配用户”并允许继续输入？
- 当用户尚未创建任何文件夹或某个文件夹下没有笔记时，主页如何展示空状态？
- 当作者尝试保存一篇未选择文件夹的笔记时，系统如何阻止保存并提示必须归档？
- 当图片无法显示或资源失效时，笔记详情页如何保留正文可读性并提示图片异常？
- 当非作者通过直接访问链接尝试进入他人笔记的编辑地址时，系统如何拒绝该操作并保留只读浏览？

## Quality & Experience Requirements *(mandatory)*

### Simplicity Guardrails

- 范围仅覆盖账号密码登录后的笔记浏览、搜索、创建、编辑、展示与一级文件夹归类，不包含评论、点赞、关注、协作编辑或多级目录。
- 每篇笔记只允许归属一个一级文件夹，避免在首版中引入多标签、多父级或嵌套目录的复杂度。

### Code Quality Requirements

- 所有用户可见行为变更都必须有对应的自动化验收或回归测试，覆盖个人主页、他人主页、笔记详情、搜索和权限限制。
- 规格、计划和任务必须保持权限边界一致：作者可编辑自己的笔记，非作者只能只读访问，任何绕过流程的直接访问也必须被拦截。

### User Experience Requirements

- 核心页面应优先保证状态清晰、模式可辨认、读写权限可感知。
- 可访问性应覆盖键盘操作、焦点可见性与语义化状态提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须允许用户使用账号和密码登录，且账号必须是全局唯一的字符串标识。
- **FR-002**: 系统必须为每个已登录用户提供个人主页，展示该用户全部已发布笔记。
- **FR-003**: 系统必须在用户主页中按一级文件夹展示笔记，且每篇笔记必须且只能属于一个一级文件夹。
- **FR-004**: 系统必须允许用户在个人主页中创建一级文件夹，以组织自己的笔记。
- **FR-005**: 系统必须允许用户从个人主页创建新笔记，并在创建时为该笔记指定所属一级文件夹。
- **FR-006**: 系统必须允许作者从个人主页或笔记详情页进入自己笔记的详情展示。
- **FR-007**: 系统必须允许作者在自己的笔记详情页中切换纯浏览模式和编辑模式。
- **FR-008**: 系统必须支持笔记内容以 Markdown 格式编写，并在展示模式中呈现解析后的阅读结果。
- **FR-009**: 系统必须允许作者在笔记内容中插入图片，并在展示模式中显示这些图片。
- **FR-010**: 系统必须允许作者更新自己笔记的标题、正文内容和所属一级文件夹，并在保存后反映到主页列表和详情页。
- **FR-011**: 系统必须提供按账号字符串进行模糊搜索的搜索框，用于查找其他用户。
- **FR-012**: 系统必须在用户选择某个搜索结果后进入目标用户主页，并展示该用户全部已发布笔记。
- **FR-013**: 系统必须允许用户打开其他用户已发布笔记的详情页进行只读浏览。
- **FR-014**: 系统必须阻止非作者编辑、保存或重新归档其他用户的笔记，即使用户通过直接链接尝试访问编辑入口。
- **FR-015**: 系统必须在登录、个人主页、他人主页、搜索结果、笔记详情和笔记保存流程中提供清晰的加载、空状态、错误提示和成功反馈。
- **FR-016**: 系统必须支持用户通过键盘完成登录、主页浏览、搜索、笔记阅读与编辑模式切换，并为主要交互元素提供清晰可见的焦点反馈与语义提示。

### Key Entities *(include if feature involves data)*

- **User Account**: 表示一个可登录并拥有唯一账号字符串的用户，包含登录凭据与个人主页归属。
- **Folder**: 表示用户主页下的一级分类容器，仅属于一个用户，用于归档该用户的笔记。
- **Note**: 表示一篇由单个作者拥有的笔记，包含标题、Markdown 正文、图片引用、所属文件夹、发布状态和可读详情页。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 的目标用户能够在首次使用时于 3 分钟内完成登录、创建文件夹、创建笔记并在个人主页重新打开该笔记。
- **SC-002**: 95% 的主页、搜索和笔记详情访问都能在 1 秒内向用户显示明确的加载、空状态或内容结果反馈。
- **SC-003**: 95% 的测试用户能够通过输入目标账号的部分字符，在 2 次选择操作内进入目标用户主页并打开一篇笔记阅读。
- **SC-004**: 在验收测试中，100% 的非作者编辑尝试都会被拦截，且不会对原笔记内容造成变更。
- **SC-005**: 在验收验证中，100% 的核心流程（登录、创建笔记、编辑笔记、搜索并阅读他人笔记）都能够通过仅键盘操作完成。

## Assumptions

- 首版仅要求已存在账号可登录使用，不包含注册、找回密码或账号审核流程。
- 新建并保存的笔记默认视为已发布内容；草稿箱、定时发布和私密可见范围不在本次范围内。
- 浏览其他用户主页与笔记的前提是访问者已登录，匿名访问不在本次范围内。
- 图片插入能力以“作者可在笔记中引用并在展示模式中看到图片”为准，不要求本次定义独立媒体管理后台。
